# 위클리 페이퍼 #12: LLM의 한계 극복과 효율적인 미세조정

## 1. LLM의 할루시네이션(Hallucination)과 문제점

### 개념

할루시네이션(환각 현상)이란 생성형 AI 모델이 사실이 아니거나, 논리적으로 모순되거나, 맥락에 맞지 않는 정보를 마치 확고한 진실인 것처럼 그럴듯하게 생성해 내는 현상을 의미합니다. LLM은 '다음 단어의 확률'을 기반으로 텍스트를 구성하기 때문에, 정보의 실제 사실 여부와 관계없이 문법적·문맥적으로 그럴듯한 문장을 만들어내면서 발생합니다.

### 왜 문제가 되는가?

* **정보 신뢰성 및 안전성 저하**: 의료, 법률, 금융, 고객 지원 등 정확성이 최우선인 전문 도메인에 적용할 경우 치명적인 오류나 의사결정 미스를 유발합니다.
* **보안 및 윤리적 위험**: 존재하지 않는 출처나 판례, 허위 사실을 유포하여 명예훼손, 편향성 강화, 사기 피해 등을 발생시킬 수 있습니다.
* **자동화 시스템의 불확실성 증대**: AI Agent나 기업 내부 워크플로우 자동화에 LLM을 도입할 때 예측 불가능한 예외 상황을 만들어 검증 비용을 대폭 증가시킵니다.

## 2. LLM 서비스들의 할루시네이션 극복 시도

| 구분 | 주요 기술/기법 | 작동 방식 및 목적 |
| --- | --- | --- |
| **외부 지식 결합** | **RAG** (Retrieval-Augmented Generation) | 검색엔진이나 기업 내부 데이터베이스에서 검증된 최신 정보를 실시간으로 조회하여 프롬프트의 맥락(Context)으로 주입합니다. |
| **정렬 및 피드백** | **RLHF / DPO** | 사람이 직접 평가하거나(RLHF) 선호도 데이터셋을 활용해(DPO) 정직하고 정확한 응답을 하도록 모델 행동을 정렬합니다. |
| **검증 및 교정** | **Self-Correction & Multi-Agent** | 생성된 응답을 별도의 검증 모델(Critic)이나 자체 재검토(Self-Consistency, CoT) 절차를 거치게 하여 스스로 오류를 수정하게 합니다. |
| **출처 명시** | **Grounding & Citation** | 모델이 답변을 생성할 때 반드시 참고한 문서의 출처나 링크를 함께 제시하도록 아키텍처 및 프롬프트를 제한합니다. |

## 3. 모델 크기를 키우는 것만으로 성능 향상이 둔화되는 이유

과거에는 파라미터 수가 증가할수록 성능이 비례하여 상승하는 스케일링 법칙(Scaling Law)이 주를 이뤘으나, 일정 시점 이후 성능 향상이 둔화(Diminishing Returns)되는 현상이 나타납니다.

* **고품질 데이터의 고갈 (Data Bottleneck)**
* 파라미터가 커질수록 필요한 학습 데이터의 양도 폭발적으로 증가합니다. 하지만 인터넷상의 고품질 텍스트 데이터는 수집 한계에 다다랐으며, 저품질/합성 데이터 위주의 학습은 오히려 모델 붕괴(Model Collapse)를 초과합니다.


* **컴퓨팅 자원 및 비용 한계**
* 모델 파라미터 확장 시 메모리(VRAM), 전력, 통신 병목 현상으로 인한 학습/추론 비용이 기하급수적으로 증가합니다. 투입 자원 대비 얻는 성능 이점이 급격히 감소합니다.


* **아키텍처 자체의 한계**
* 트랜스포머(Transformer) 아키텍처는 시퀀스 길이가 길어질수록 $O(N^2)$의 연산 복잡도를 가집니다. 본질적으로 '확률적 다음 단어 예측' 방식에 의존하므로, 크기를 키우는 것만으로는 추론, 복합 논리, 장기 기억 능력을 완전하게 해결하기 어렵습니다.

## 4. PEFT(Parameter-Efficient Fine-Tuning)의 필요성과 효과적인 상황

### PEFT가 필요한 이유

* **자원 및 비용의 극적 절감**: 수십억~수천억 개의 전체 파라미터를 업데이트하는 Full Fine-Tuning은 막대한 GPU 자원이 필요합니다. PEFT는 전체 파라미터의 1% 미만(어댑터 등)만 학습시키므로 메모리 소모량과 계산 시간을 파격적으로 줄입니다.
* **파괴적 망각(Catastrophic Forgetting) 방지**: 기존 베이스 모델의 범용적인 지식 체계를 고정한 채 소수의 파라미터만 조정하므로, 특정 작업 학습 시 기존 지식을 잃어버리는 현상을 방지합니다.
* **효율적인 모델 관리**: 하나의 베이스 모델을 공유하면서, 용도별로 수십 MB 수준의 가벼운 어댑터(Adapter) 모듈만 교체하여 다목적 서비스를 운영할 수 있습니다.

### 특히 효과적인 상황

1. **단일/소형 GPU 등 한정된 자원 환경**: A100/H100 등 고가의 대규모 클러스터 없이 일반적인 개발 환경에서 도메인 맞춤 모델을 구축할 때.
2. **다중 사용자/업무 맞춤형 서비스 구축**: 하나의 LLM을 베이스로 두고, 고객사별·부서별로 서로 다른 작업(요약, 코드 생성, 번역 등)을 수행하는 어댑터(LoRA 등)를 동적으로 교체·배포해야 할 때.
3. **빠른 실험과 프로토타이핑이 필요한 경우**: 특정 특화 도메인(의료, 법률 등) 데이터셋으로 신속하게 테스트하고 서비스를 상용화해야 할 때.
